# Lottie assets

`01-like.json`, `02-comment.json`, `03-subscribe.json` are standalone Lottie
animations for the three scenes (1080×1920, 60fps, transparent background).
They're generated by `build-lottie.mjs` — edit the `CONFIG` block at the top
of that file (colors, text, timing) and re-run:

```bash
node lottie/build-lottie.mjs
```

## Why generated instead of hand-written

Lottie's JSON format (bezier easing handles, per-property keyframe arrays,
layer parenting) is tedious and easy to get subtly wrong by hand. The
generator keeps all three scenes structurally consistent and makes
re-tuning a one-line change instead of a JSON-surgery session.

## Playing them

Any standard Lottie player works — for example, with
[lottie-web](https://github.com/airbnb/lottie-web):

```html
<div id="anim" style="width:360px;height:640px"></div>
<script src="lottie.min.js"></script>
<script>
  lottie.loadAnimation({
    container: document.getElementById("anim"),
    renderer: "svg", // or "canvas"
    loop: false,
    autoplay: true,
    path: "01-like.json",
  });
</script>
```

Or preview instantly by dragging a file onto
[lottiefiles.com/preview](https://lottiefiles.com/preview) or the
[LottieFiles VS Code extension](https://marketplace.visualstudio.com/items?itemName=LottieFiles.jsonlottie).

## Importing into After Effects

Lottie JSON round-trips into After Effects via the (free)
[Bodymovin](https://github.com/airbnb/lottie-web/tree/master/scripts) / LottieFiles
AE plugin's *import* feature, or third-party importers like **lottie-to-ae**.
Once imported you get real AE shape/text layers you can keyframe further,
re-render with your own effects, or hand off to a motion designer.

## Fidelity notes (read before assuming pixel-parity with the web version)

The web version (`../index.html`) is the source of truth for the final
look. The Lottie files are a faithful **choreography** rebuild — same
timing, same colors, same layer structure — using native Lottie/AE
primitives, with a few things simplified because they don't map cleanly
onto baked vector shapes:

- **No backdrop blur.** CSS `backdrop-filter: blur()` (the glassmorphism
  look) has no equivalent in Lottie shape layers. The card is approximated
  with a translucent dark fill plus a soft glow ellipse behind it — reads
  the same at a glance, but doesn't actually blur whatever is behind it.
- **No per-character typewriter reveal.** The Comment scene's subtitle
  fades in as a whole rather than typing itself out character-by-character
  (the blinking cursor is still there and still timed correctly).
- **No motion-blur trail.** The web version adds a transient CSS blur during
  fast enter/exit moves; the Lottie version relies on the eased position
  keyframes alone (still smooth, just without the extra blur trail).
- **Icons are simplified geometric glyphs** (rounded rects / ellipses /
  simple paths), not the exact SVG path data used in `../assets/icons/` —
  close enough to read correctly at intro size, but a designer polishing
  this in After Effects will likely want to trace the real icons in.
- **Font:** layers reference `Inter-Bold`. Lottie players resolve fonts by
  name at playback time — for a web player, load the same family via
  `@font-face`/Google Fonts; for After Effects, just reassign the layer's
  font after import.

If you need a pixel-exact Lottie of the *actual* DOM/CSS animation, the
more reliable path is: open `../index.html` in After Effects–adjacent
tooling that can trace it, or treat `../export/` (frame-accurate video
render of the real web version) as the source of truth and use these
Lottie files only where a native vector asset is required.
